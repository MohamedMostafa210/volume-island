# NumberKeys decision log

- 31 Oct 2026: GitHub cloud builds + Sideloadly weekly reinstall (no Mac, no paid account).
- 6 Nov 2026: NumberKeys built as two keyboard extensions (EN/AR) in the same repo.
- 6 Nov 2026: v2 added Gboard features, learning predictions, swipe gestures, clipboard history; reduced height.
- 6 Nov 2026: v3 goal set — native-level speed and main-keyboard readiness.
- 6 Nov 2026: v3 audit done (11 causes of slowness, ranked). Plan approved: overlay first, then cheap keystrokes, then text cache, then the rest (background predictions, compact word list, startup, saving, delete/cursor, rendering, clipboard).
- 6 Nov 2026: Hidden speed overlay added (Perf.swift). It is toggled by holding the clipboard button for 1.2 s, not by a switch in the container app, because sharing a setting between app and keyboard needs an App Group, which a free Apple ID may not allow. Off by default.
- 6 Nov 2026: First speed numbers on the phone (before phases A-C): launch 104 ms, touch to popup 22 ms, lift to text 20 ms, worst about 100 ms, memory 25.5 MB. Felt heavy, some fast taps missed.
- 6 Nov 2026: Phase A (missed taps). Cancelled quick taps now still type; space and return commit early when the next key lands (fixes "hellow orld"); held keys commit oldest first; symbol menu opens at 0.45 s and only if the finger is still (was 0.3 s, typed symbols by accident); taps up to 8 pt above the top row count. Speed meter now splits iOS delivery vs our code, counts taps vs typed and lost frames.
- 6 Nov 2026: Phase B (main-thread speed). All word work (loading, predicting, learning, saving) runs on one background queue; old answers are thrown away. Word lookup uses a sorted list + binary search instead of scanning 25k words. Apple's UITextChecker replaced by our own one-typo guesses (UIKit is not safe off the main thread). Learned words saved 3 s after typing stops and on close, capped (5000 words, 3000 pairs x 12 followers). Key click is Apple's own (follows the Keyboard Clicks setting); haptics pre-warmed. Emoji and clipboard panels are built on first use. Did NOT switch to a precompiled word file: loading is off the main thread now, so it is not worth changing the build workflow.
- 6 Nov 2026: Phase C (settings). Hold the emoji key to open settings: number row on/off (off = Apple-style 4-row keyboard and Apple-style 123 / #+= pages; rare symbols moved to long-press), symbol hints on/off, speed meter on/off. Settings live inside each keyboard (EN and AR separately) because sharing with the app needs an App Group, which a free Apple ID may not allow. The hidden clipboard-button hold for the meter was removed.
- 6 Nov 2026: Phase D (identical Apple look) waits for screenshots of Apple's keyboard.
- 6 Nov 2026: Keys are now redrawn only when something visible changes (mode, shift, theme, return key), not on every keystroke. Text before the cursor is kept in our own copy and re-checked once after typing pauses (0.4 s), so typing no longer reads the text field 3-4 times per key. Hold-delete and cursor-swipe no longer rebuild keys or recompute suggestions on every step.
